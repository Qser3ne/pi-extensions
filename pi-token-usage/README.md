# pi-token-usage

通过一个 Pi 命令，查询本机所有项目、会话和渠道的已保存 token 用量。无需连接服务商接口，不产生模型调用。

## 使用

```text
/tokens 24h
/tokens 3d
/tokens 7d
/tokens 30d
/tokens 12h
/tokens 15d
```

仅支持 `/tokens xh`（最近 x 小时）和 `/tokens xd`（最近 x 天）；x 为正整数，必须带单位。单独输入 `/tokens` 只提示用法，不执行查询。不提供独立快捷命令。

结果显示准确整数总量，以及输入、输出、缓存读取、缓存写入四项明细；不使用 K/M 缩略值。报告可在 TUI 历史中查看，不进入模型上下文，也不会触发模型回复。RPC 模式另发送文本通知。

## 本地试用与安装

环境：Node.js >=22.19.0、Pi（已针对 1.5.0 验证）。

从工作区根目录临时试用，不修改设置：

```bash
pi -e ./pi-token-usage/src/index.ts
```

需要长期加载时，**自行选择**安装本地包：

```bash
pi install ./pi-token-usage
```

安装完成后在会话中执行 `/reload`。本地安装引用目录本身，请保留该目录；本包尚未发布远程仓库或 npm。

## 统计口径

- 汇总所有 provider，不受当前项目、当前模型或当前会话限制；安装前已有的历史也能查询。
- 时间从查询开始时刻向前滚动，1 天恒为 24 小时，不按日历日/午夜划分；上下界均计入。
- 来源是 Pi agent 数据目录下的 `sessions/`（递归，包含已保存子代理）以及当前会话的 `getSessionDir()`。使用 Pi 的 `getAgentDir()`，支持自定义 `PI_CODING_AGENT_DIR`。
- 其他未纳入这些根目录的自定义会话、其他机器、其他客户端、已删除历史、未保存的会话，以及 provider 未报告的用量均无法保证覆盖。不会扫描整个磁盘或读取账号凭据。为避免越界，递归时不跟随内部符号链接；可直接选择的根目录会先解析真实路径。
- 包含 assistant 回复、工具报告的嵌套模型用量、缓存预热、压缩摘要和分支摘要的真实 usage。放弃的分支仍计入；fork/clone 中复制的同一原始条目只计一次。
- 总量优先采用有效 `totalTokens`，缺失时采用 `input + output + cacheRead + cacheWrite`。思考 token 已属于 output，1h 缓存写入已属于 cacheWrite，不再次相加。不同 provider 的统计定义由 Pi 归一化，不等于服务商账单。
- 已识别的 pi-subagents / bg_wait 父级汇总优先用子会话自身的 assistant 用量覆盖，避免父子相加。继承的父会话上下文、独立缓存预热/压缩和后代代理用量不充当本次调用的覆盖依据，它们的真实记录仍分别统计。子记录丢失时，仅把未覆盖差额按父汇总时间回退；此时会警告时间归属不精确。重复的有身份汇总仅保留最大累计值；多个汇总或子会话历史无法证明独立调用边界时会明确警告，结果可能是下界。
- 无法识别身份的子代理汇总保留并警告可能重叠；不承诺此时无重复。来源缺失、损坏行、缺失 usage 等都会明确提示。末行尚未写完时暂不计入，下次查询再读取，不估算文本 token。
- 无记录显示 0。查询过程中到达的新记录属于下次查询，当前查询的截止时刻不变。

## 缓存

默认位置：

```text
~/.pi/agent/pi-token-usage/cache-v1/
```

自定义 agent 目录时跟随该目录。首次查询需扫描历史，数据多时可能较慢；之后复用未变化文件、仅解析追加的完整行。文件替换/截断/同大小改写会使对应缓存失效。追加路径检查文件身份、前缀及追加边界；不针对恶意伪造文件元数据或刻意保留这些采样区的原地历史改写提供防篡改保证。

缓存只包含时间、用量、记录哈希和最小来源信息，不保存对话正文。逐文件以临时文件加原子替换写入，支持多个 Pi 会话同时查询。坏缓存自动重建；缓存无法写入时仍完成统计并提示。

可在 Pi 空闲时删除上述扩展缓存目录，下次会重新扫描。删除源会话后，其缓存不会继续作为历史账本计入；本扩展不负责备份。不要删除源 `sessions/` 来清理本扩展缓存。
