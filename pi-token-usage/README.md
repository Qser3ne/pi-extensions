# pi-token-usage

通过两个 Pi 命令，查询本机跨项目、跨会话的已保存 token 用量；仅统计当前 `/model` 默认列表中的模型。无需连接服务商接口，不产生模型调用。

## 使用

```text
/token-usage
/token 24h
/token 7d
/token 12h
```

`/token-usage` 固定查询近 24 小时，不接受参数。`/token xh`（最近 x 小时）和 `/token xd`（最近 x 天）支持指定范围；x 为正整数，必须带单位。单独输入 `/token` 只提示用法，不执行查询。原 `/tokens` 已移除，不保留别名。

两个命令均在执行时读取 Pi 当前已加载的模型名单：有非空 `scoped-models` 时使用该范围，否则使用全部当前可用模型。对应 `/model` 打开时默认展示的范围，不跟随选择器临时搜索词或临时切换的 all/scoped 视图。精确匹配 `provider/model ID`，同名模型不跨渠道匹配。不主动刷新目录、解析认证或请求服务商；修改配置后需先让 Pi 正常加载变更。

结果显示整数总量，以及输入、输出、缓存读取、缓存写入四项明细和**缓存命中率**；不使用 K/M 缩略值。报告同时按 **provider/model** 展示上述用量和命中率，替换原来的 provider 明细；同名模型在不同渠道分别统计。整体总量、记录数、明细和缓存率都按同一模型白名单过滤。仅展示名单内、查询窗口内实际有用量的组合，按总 token 降序排列；全零、仅窗口外使用或从未使用的模型不显示，不为空模型补零占位。任一 token 分项或总量大于 0 即视为有用量。报告可在 TUI 历史中查看，不进入模型上下文，也不会触发模型回复。RPC 模式另发送文本通知。报告不显示来源脚注；统计覆盖范围与限制见下文。

缓存命中率 = `缓存读取 ÷（普通输入 + 缓存读取 + 缓存写入）× 100%`，保留两位小数，不包含输出；没有输入时显示 `—`。整体和各 provider/model 均先汇总 token，再计算比例，不平均各条记录的百分比。缓存写入计入分母，但不算命中。

provider 和 model 只取源记录中明确保存的字段，不从当前模型、父代理或相邻记录推断。缺少任一归属、或不在当前名单内的记录不计入新查询；原历史和两级缓存仍完整保留，各模型分组之和与整体用量一致。新报告标题标记“当前模型列表”，指查询执行时的名单。已保存旧报告不重新过滤、不改写旧数据：缺少范围标记时保留“所有渠道”；没有模型明细时（即使有旧 provider 明细）只展示整体，不把 provider 当成模型。旧报告的缺失标签仍可显示为“未知渠道”和“未知模型”。

## 本地试用与安装

环境：Node.js >=22.19.0、Pi（已针对 1.5.0 验证）。

从工作区根目录临时试用，不修改设置：

```bash
pi -e ./pi-token-usage/src/index.ts
```

需要长期加载时，**自行选择**安装本地包：

```bash
pi install ./pi-token-usage
```

安装完成后在会话中执行 `/reload`。本地安装引用目录本身，请保留该目录；本包尚未发布远程仓库或 npm。

## 统计口径

- 扫描范围不受当前项目和会话限制；安装前已有的历史也能查询。统计范围受当前模型名单限制，不是只统计当前正在使用的单一模型。
- 时间从查询开始时刻向前滚动，1 天恒为 24 小时，不按日历日/午夜划分；上下界均计入。
- 来源是 Pi agent 数据目录下的 `sessions/`（递归，包含已保存子代理）以及当前会话的 `getSessionDir()`。使用 Pi 的 `getAgentDir()`，支持自定义 `PI_CODING_AGENT_DIR`。
- 其他未纳入这些根目录的自定义会话、其他机器、其他客户端、已删除历史、未保存的会话，以及 provider 未报告的用量均无法保证覆盖。不会扫描整个磁盘或读取账号凭据。为避免越界，递归时不跟随内部符号链接；可直接选择的根目录会先解析真实路径。
- 包含 assistant 回复、工具报告的嵌套模型用量、缓存预热、压缩摘要和分支摘要的真实 usage。放弃的分支仍计入；fork/clone 中复制的同一原始条目只计一次。
- 总量优先采用有效 `totalTokens`，缺失时采用 `input + output + cacheRead + cacheWrite`。思考 token 已属于 output，1h 缓存写入已属于 cacheWrite，不再次相加。不同 provider 的统计定义由 Pi 归一化，不等于服务商账单。
- 已识别的 pi-subagents / bg_wait 父级汇总优先用子会话自身的 assistant 用量覆盖，避免父子相加。继承的父会话上下文、独立缓存预热/压缩和后代代理用量不充当本次调用的覆盖依据，它们的真实记录仍分别统计。子记录丢失时，仅把未覆盖差额按父汇总时间回退；此时会保留时间归属不精确的诊断。重复的有身份汇总仅保留最大累计值；多个汇总或子会话历史无法证明独立调用边界时会保留诊断，结果可能是下界。子会话自身的用量按其 provider/model 归属，无法确定归属的汇总及未覆盖差额在内部保留为未知，不归给父代理；由于无法匹配模型白名单，不计入新查询。
- 在完整历史上先进行继承去重和子代理协调，再按模型名单过滤，防止排除某些子模型后错误计回父级汇总。无法识别身份的汇总仍在内部记录可能重叠的诊断；未知归属不计入新查询，不承诺所有来源已完整覆盖。来源缺失、损坏行、缺失 usage 等诊断仍收集并保存到报告数据，但界面不显示“数据存在缺失或不精确部分”标题和警告列表。参数错误和真正查询失败仍正常提示；隐藏诊断不代表数据完整。末行尚未写完时暂不计入，下次查询再读取，不估算文本 token。
- 当前模型名单为空或没有符合条件的记录时显示 0，不回退全历史；名单读取真正失败时提示查询错误。查询过程中到达的新记录属于下次查询，当前查询的截止时刻不变。

## 缓存

默认位置：

```text
~/.pi/agent/pi-token-usage/cache-v1/
```

自定义 agent 目录时跟随该目录。每次仍递归发现会话文件；目录检查最多 8 路并发，利用目录条目类型跳过无关文件和内部符号链接，后续文件读取最多 4 路。首次查询需扫描历史，数据多时可能较慢；之后复用未变化文件、仅解析追加的完整行。文件替换/截断/同大小改写会使对应缓存失效。文件快照协议已升级至 4（包含 model 归属）：旧缓存会自动从源会话重建，升级后首次查询可能重新扫描；目录名仍为 `cache-v1`，无需手动删除。追加路径检查文件身份、前缀及追加边界；不针对恶意伪造文件元数据或刻意保留这些采样区的原地历史改写提供防篡改保证。

缓存只包含时间、用量、provider/model 归属、记录哈希和最小来源信息，不保存对话正文。逐文件以临时文件加原子替换写入，支持多个 Pi 会话同时查询。坏缓存自动重建；缓存无法写入时仍完成统计并保留内部诊断。

同一扩展实例还会保留有上限的内存快照，避免重复读取、解析磁盘统计 JSON；每次仍检查源文件身份、大小及修改时间，并重新计算窗口、去重、子代理协调及当前模型名单过滤，不复用最终报告。名单变化无需清空缓存，不会丢失先前被排除模型的历史。内存最多保留 4096 个文件，按序列化统计元数据计重的额度为 64 MiB（不是精确 JavaScript 堆上限）；超大项不保留，容量满时淘汰较旧访问项。磁盘保存失败的新快照不进入内存，后续查询继续重试。Pi 重启或 `/reload` 会清空该实例内存。

可在 Pi 空闲时删除上述扩展缓存目录；若要同时清除当前进程内快照并强制重新扫描，请删除后执行 `/reload`。否则当前实例仍可能复用经过源文件检查的内存快照，重启后再重建磁盘缓存。删除源会话后，其缓存不会继续作为历史账本计入；本扩展不负责备份。不要删除源 `sessions/` 来清理本扩展缓存。
