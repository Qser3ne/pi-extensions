# token-usage

## Purpose

通过 Pi 用户命令查询本机已保存会话在滚动时间窗口内的 token 用量，跨项目和会话汇总，展示整体及各 provider/model 组合的用量与缓存命中率，统计范围以本机保留的历史及查询执行时的当前模型名单为边界。

## Requirements

### Requirement: 用量查询命令

扩展 SHALL 仅注册 `token` 与 `token-usage`。`/token xh` 和 `/token xd` 的 x SHALL 为可安全表示的正整数，MUST NOT 接受省略单位的数字；`/token-usage` SHALL 固定查询执行开始时刻向前 24 小时，不接受额外参数。

#### Scenario: 小时和天数查询

- **WHEN** 用户执行 `/token 24h` 或 `/token 7d`
- **THEN** 扩展分别查询从执行开始时刻向前 24 小时或 7 × 24 小时的用量
- **AND** 时间窗口两端均包含在内，不按本地午夜划分

#### Scenario: 近一天快捷查询

- **WHEN** 用户执行不带参数的 `/token-usage`
- **THEN** 按同一执行截止点，查询范围及统计口径与 `/token 24h` 相同，不按自然日划分

#### Scenario: 无参数或非法参数

- **WHEN** 用户执行 `/token`、`/token 15`、`/token help` 或传入零、负数、小数、非法单位或溢出时长，或给 `/token-usage` 传入额外参数
- **THEN** 扩展显示用法或错误，不读取模型名单、不执行统计查询、不触发模型回复

### Requirement: 本机记录覆盖边界

扩展 SHALL 递归读取 Pi agent 数据目录的 `sessions/` 和当前会话的非空存储目录，包含其中已保存的子代理。来源发现 MUST NOT 因当前项目或模型名单而跳过历史文件；最终统计 SHALL 应用当前模型名单。扩展 MUST NOT 读取凭据、查询服务商后台或扫描未选择的磁盘目录。

#### Scenario: 跨项目和渠道

- **WHEN** 被扫描目录内的多个项目或 provider 在窗口内有有效用量记录
- **THEN** 符合当前模型名单的记录参与总量统计，安装前的已有记录也可查询

#### Scenario: 根目录别名和内存会话

- **WHEN** 用户选择的根目录是符号链接，或当前会话没有持久化目录
- **THEN** 被选根目录的别名及子会话引用按同一物理来源匹配
- **AND** 空会话目录不会展开为当前工作目录，递归过程不跟随目录内部的任意符号链接

#### Scenario: 不可覆盖的历史

- **WHEN** 用量发生在其他机器、其他客户端、未选择的自定义存储目录，或源记录已删除、未保存、未报告 usage
- **THEN** 扩展不承诺恢复这些用量；统计仅涵盖本机已保存记录，不等于服务商账单

### Requirement: 当前模型名单过滤

所有用量查询命令 SHALL 在执行时获取 Pi 已加载的本地模型快照：有非空 scoped 模型范围时使用该范围，否则使用全部当前可用模型，对应 /model 选择器默认展示范围。扩展 MUST NOT 为此刷新远端目录、解析认证或生成回复，也不跟随选择器的临时搜索或临时 all/scoped 视图切换。

#### Scenario: 精确匹配与一致统计

- **WHEN** 历史存在同名跨渠道模型、名单外模型或缺少 provider/model 的记录
- **THEN** 仅按 provider 与 model ID 二元组精确匹配，不按显示名称或单一当前模型推断
- **AND** 整体、明细、记录数和缓存率统一只统计匹配记录；未知归属不计入结果，真实字面 unknown/null 不与缺失字段混淆

#### Scenario: 名单变化和空名单

- **WHEN** 用户改变 scoped 范围或 Pi 当前可用名单，或没有任何当前可用模型
- **THEN** 下一次查询使用新快照；空名单显示零，不回退全历史
- **AND** 名单读取真正失败时显示查询错误，不生成无过滤报告

#### Scenario: 完整协调后筛选

- **WHEN** 同一子代理汇总包含名单内与名单外模型，或用户复用缓存查询不同名单
- **THEN** 先在完整历史上处理继承去重及父子用量协调，再过滤统计
- **AND** 文件/内存快照保留全部记录，不因筛选删除模型或未知历史；切换名单不必重建缓存

### Requirement: 有界目录发现

扩展 SHALL 在每次查询时发现所选根目录中的普通 JSONL 会话文件，MUST NOT 因缓存存在或文件较旧而省略来源发现。目录检查 SHALL 最多 8 路并发，后续会话文件读取 SHALL 最多 4 路并发；并发 MUST NOT 扩大符号链接扫描边界。

#### Scenario: 宽目录与重叠根

- **WHEN** 存在多个子目录、多个重叠根或显式选择的会话文件
- **THEN** 在有界并发下发现相同候选集合，去重并稳定排序；空路径不展开为 cwd
- **AND** 排队目录在读取前已变为符号链接时不跟随它

### Requirement: 真实用量口径

扩展 SHALL 统计 assistant 回复、工具结果报告的嵌套模型 usage、独立 usage 条目、压缩摘要和分支摘要的有效用量。总量 SHALL 优先使用有效 `totalTokens`，缺失时以 `input + output + cacheRead + cacheWrite` 回退。扩展 MUST NOT 估算文本 token 或把上下文长度当成消耗。

#### Scenario: 缓存及思考用量

- **WHEN** 记录包含输入、输出、缓存读取、缓存写入以及 reasoning 或 cacheWrite1h
- **THEN** 分别汇总四项主要明细
- **AND** reasoning 已属于输出、cacheWrite1h 已属于缓存写入，不再次相加

#### Scenario: 原始事件时间

- **WHEN** 旧会话在查询窗口内继续产生用量，或扫描过程中追加了查询终点之后的更大汇总
- **THEN** 以各用量记录的时间归属窗口，而不是文件创建或修改时间
- **AND** 查询终点之后的汇总不能替换窗口内的有效统计

### Requirement: provider/model 分组与缓存命中率

扩展 SHALL 在整体及各 provider/model 组合中显示总量、输入、输出、缓存读取、缓存写入与缓存命中率，MUST NOT 另附独立 provider 汇总区。缓存命中率 SHALL 为 `cacheRead / (input + cacheRead + cacheWrite) × 100%`，输出 MUST NOT 计入分母。分组 SHALL 按总 token 降序；同量按 provider、model 名称的字符串顺序稳定排序。

#### Scenario: 汇总后的加权比例

- **WHEN** 窗口内有不同调用规模、不同缓存效果的记录
- **THEN** 整体与每个 provider/model 组合均先汇总各输入侧分项，再计算命中率，不平均单条记录百分比
- **AND** 百分比保留两位小数；没有输入侧 token 时显示 `—`，不显示 NaN 或 Infinity

#### Scenario: 渠道与模型共同归属

- **WHEN** 同一 provider 使用不同模型，或同名模型出现在不同 provider 下
- **THEN** 各组合分别统计，同一组合的多次调用累计
- **AND** 组合身份不因名称包含斜线、字面 unknown 或原型键而碰撞

#### Scenario: 明确归属与未知元数据

- **WHEN** 用量记录的 provider、model 字段明确，或其中某个字段缺失/无效
- **THEN** 仅采用源记录自身的明确字段，去除字段首尾空白，不从当前模型、父代理、相邻消息或路径猜测
- **AND** 未知元数据仍完整保存在快照中，但不进入新查询；各分组的分项之和与整体一致，同一原始事件的复制历史只参与一个分组

#### Scenario: 子代理的模型归属

- **WHEN** 已有子会话自身的真实用量，或父级汇总仍存在未覆盖差额
- **THEN** 子记录保留其自身 provider/model，无法确定归属的汇总及差额列入未知，不借用父代理 provider 或 model

### Requirement: 仅展示窗口内实际使用的模型

扩展 SHALL 仅从窗口内去重后的实际记录建立 provider/model 明细，MUST NOT 枚举配置中的模型填充占位项。组合 SHALL 在任一 token 分项或 totalTokens 大于 0 时显示；过滤全零组合 MUST NOT 改变整体用量和整体记录数语义。

#### Scenario: 全零或窗口外模型

- **WHEN** 某组合所有 token 字段均为 0、仅在窗口外使用，或从未产生用量记录
- **THEN** 模型明细不显示该组合

#### Scenario: 总量与分项不一致但存在用量

- **WHEN** 某组合 totalTokens 为 0 但至少一个分项为正，或仅 totalTokens 为正而分项全零
- **THEN** 仍显示该组合，保留源记录的总量口径，不因字段不一致隐藏实际用量

### Requirement: 复制历史和子代理协调

扩展 SHALL 对 fork/clone 复制的相同用量事件去重，保留内容、时间等事件身份区分，MUST NOT 仅凭短条目 ID 去重。Pi 分支重接树链接本身 MUST NOT 被当成新消耗。被放弃的分支仍 SHALL 参与实际消耗统计。

#### Scenario: 带标签的 Pi 分支

- **WHEN** Pi 复制包含用量的历史并因移除标签而重接 parentId
- **THEN** 同一原始用量仍只计一次，不因树链接变化翻倍

#### Scenario: 可覆盖的原生子代理汇总

- **WHEN** 原生 pi-subagents 或 bg_wait 汇总可以通过已扫描子会话的自身 assistant 用量覆盖
- **THEN** 不再把该汇总作为独立消耗与子会话相加
- **AND** 继承的父历史、独立缓存预热、压缩用量和后代代理用量不充当本次调用自身用量的覆盖依据

#### Scenario: 子代理不完整或调用边界不明

- **WHEN** 子会话缺失、不完整，或重复汇总/重试历史不能证明独立调用边界
- **THEN** 可识别汇总按身份协调，仅保留最大值回退，未覆盖差额按父级汇总时间归属
- **AND** 报告数据保留时间或完整性不精确、可能是下界的诊断；无法识别身份的汇总在协调中保留并记录可能重叠的诊断，最终仍遵循名单过滤，不宣称精确全量

### Requirement: 报告不进入模型上下文

扩展 SHALL 显示时间范围、当前模型名单范围内总量、输入/输出/缓存读取/缓存写入明细、整体及各模型组合的缓存命中率，token 数值使用完整整数而非 K/M 缩略。报告 MUST NOT 展示来源脚注，MUST NOT 触发模型调用或进入后续模型上下文。

#### Scenario: TUI 和 RPC 查询

- **WHEN** 用户在 TUI 中查询成功
- **THEN** 结果作为可持续查看的自定义条目保存及渲染
- **AND** RPC 模式另以 info 级别文本通知发送结果，不因保留的隐藏诊断使用 warning 级别

#### Scenario: 兼容已保存旧报告

- **WHEN** 历史报告数据没有 models 分组字段，即使保留旧 providers 字段
- **THEN** 仍能显示原有整体数据并计算整体缓存命中率，不把 provider 当成模型或编造模型明细

#### Scenario: 已保存报告的范围标记

- **WHEN** 展示成功的新查询报告或缺少范围标记的旧报告
- **THEN** 新报告数据保存 scope=current-models，标题显示“当前模型列表”，指查询时的范围
- **AND** 旧报告不重新过滤或改写，缺少 scope 时仍显示“所有渠道”；已有未知归属分组仍可显示其缺失标签

#### Scenario: 不显示来源脚注

- **WHEN** 渲染当前、旧版或空报告，或通过 RPC 通知发送结果
- **THEN** 不显示“来源：本机 Pi 已保存记录（跨项目、跨会话、含已保存子代理；非服务商账单）”及其尾部空行
- **AND** 仅移除展示文字，统计范围与用量计算口径不变

#### Scenario: 会话在查询中被替换

- **WHEN** 查询未完成前发生会话关闭或替换
- **THEN** 原查询不向失效会话写入报告

### Requirement: 可重建的增量缓存

扩展 SHALL 在 agent 数据目录的 `pi-token-usage/cache-v1/` 维护可删除重建的统计缓存，仅保存时间、usage、明确的 provider/model、事件哈希和最小来源信息，MUST NOT 保存对话正文。缓存 SHALL 支持独立进程并发查询，不把缓存当成永久账本。

#### Scenario: 重复查询和常规源文件变化

- **WHEN** 源文件未变化，或仅追加完整记录
- **THEN** 扩展复用已有统计或解析新增完整行
- **AND** 文件快照只接受当前协议 4；发现替换、截断、同大小改写或无效/旧协议快照时重新扫描对应文件，已删除源文件不继续累计

#### Scenario: 缓存故障或历史原地改写

- **WHEN** 没有可用内存快照，且磁盘缓存不可读写或快照损坏
- **THEN** 扩展回退到可用的源记录扫描，并在不能使用缓存时保留内部诊断
- **AND** 缓存追加校验不提供针对恶意元数据伪造或刻意保留采样区的原地历史改写的防篡改保证

### Requirement: 限额内存快照与实时校验

扩展 SHALL 为每个实例保留独立、按磁盘缓存目录及源文件路径区分的统计快照，MUST NOT 保存正文或最终查询报告。保留额度 SHALL 为最多 4096 个文件以及按序列化元数据计重的 64 MiB，MUST NOT 宣称它是精确 JavaScript 堆上限；超大项不接纳，容量满时按访问顺序淘汰。

#### Scenario: 重复查询和源文件变化

- **WHEN** 同一实例重复查询、切换查询时间窗口，或源文件追加、改写、替换、删除或不可读取
- **THEN** 每次仍核对源文件身份、大小及修改时间，只复用有效快照，并重新执行时间过滤、去重和父子协调
- **AND** 已删除或不可读来源不因内存中残留的统计而继续累计；不同实例和磁盘缓存目录不共享状态

#### Scenario: 新快照保存失败及恢复

- **WHEN** 读取了变化源文件，但新快照无法保存到磁盘
- **THEN** 仍统计本次有效用量、保留内部诊断，不将该新快照留在内存掩盖故障，并在下次继续重试
- **AND** 写入恢复后重新落盘并允许内存复用

#### Scenario: 清空缓存与生命周期

- **WHEN** 用户重启 Pi 或执行 /reload
- **THEN** 原实例的内存快照被清空，新实例重新建立自己的快照
- **AND** 仅删除磁盘缓存目录不保证清空当前内存；要强制两级缓存一起清空并重新扫描，用户删除磁盘目录后执行 /reload

### Requirement: 数据诊断保留与展示边界

扩展 SHALL 对损坏行、无效时间/usage、缺失用量、无法读取的文件及不完整末行收集诊断并保存在报告数据中。界面 MUST NOT 展示“数据存在缺失或不精确部分”标题及其整块警告列表，MUST NOT 因隐藏警告而宣称完整准确账单。没有有效记录时 SHALL 显示 0。

#### Scenario: 活跃文件末行未完成

- **WHEN** 扫描遇到尚未写完的 JSONL 末行或跨块 UTF-8 内容
- **THEN** 本次不计入不完整末行，下次读取补全后恰好统计一次

#### Scenario: 部分可用数据

- **WHEN** 一部分源记录损坏或不可读，其余记录有效
- **THEN** 统计其余有效记录并保留完整性诊断，不展示警告块，不以文本估算弥补缺失

#### Scenario: 真正错误仍提示

- **WHEN** 参数无效或整个查询因安全整数溢出等原因失败
- **THEN** 仍正常显示参数 warning 或查询失败 error，不生成成功报告
