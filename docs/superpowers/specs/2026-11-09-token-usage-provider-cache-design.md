# Provider 用量与缓存命中率设计

状态：用户已确认，2026-11-09。

## 目的与范围

在现有 `/tokens xh`、`/tokens xd` 报告中比较整体及不同 provider 的 token 用量和缓存效果。不增加命令、依赖、网络调用或模型调用；继续跨项目、跨会话读取本机已保存历史。

## Approaches

- 采用输入缓存命中率：`cacheRead / (input + cacheRead + cacheWrite) × 100%`。与核对的 Sub2API 当前趋势图口径一致，输出长度不影响结果；用户已确认。
- 不采用 `cacheRead / totalTokens`：它是总用量中的缓存占比，会随输出变化，不适合比较输入缓存效果。
- 直接扩展现有报告，不新增独立命令或查询入口，保持原有使用方式。

## 行为

- 整体显示总量、四项明细和缓存命中率；百分比保留两位小数，分母为 0 时显示 `—`。
- 按 provider 显示同样的用量明细和缓存命中率，按 totalTokens 降序、相同总量按 provider 名称稳定排序。百分比从各分项汇总后计算，不平均单条或分组百分比。
- 总量口径保持不变：优先记录的有效 totalTokens，缺失时四项相加。
- 每条有效用量在现有时间过滤、历史去重、父子汇总协调后，只归入一个 provider 分组，分组各分项之和等于整体各分项。
- provider 只使用用量记录自身明确的归属；不从当前选中模型、父代理、相邻消息或文件路径猜测。无法归属的记录显示“未知”。真实 provider 字符串与未知桶用不同内部表示，避免名称碰撞。
- 子会话真实记录按自己的 provider 计入；无法确定 provider 的子代理汇总及未覆盖差额归入未知，不借用父代理 provider。
- 隐藏完整的“数据存在缺失或不精确部分”标题及警告列表。底层仍收集诊断，保存进报告数据；RPC 报告不因为这些隐藏警告使用 warning 级别。真正查询失败、参数错误提示保持。
- 不追加新的精度保证文案，不把数据不完整假装成完整账单。

## 实现边界（实现者的决定）

- 沿用 TypeScript、Node 内置测试和现有 TUI Text renderer，修改读取、聚合、格式化与缓存验证，不重构采集流程。
- 在统计记录中新增可选 provider；新增 provider 汇总数组。无记录时整体为 0、缓存命中率为 `—`，不创建虚假分组。
- 文件缓存协议从 2 升到 3，旧缓存自动从源历史重建，目录仍保留 cache-v1。升级后首次查询可能重新扫描历史。
- 已保存的旧报告缺少 provider 数组时仍可渲染：保留整体数据并计算整体缓存命中率，不虚构 provider 明细。
- 仅缓存 provider 及统计元数据，继续不保存消息正文。
- 不修改 settings，不覆盖现有 pi-qser3ne-patch 和 AGENTS.md 改动；不推送远程。
