# Token 用量查询性能优化设计

状态：用户已批准，并授权制定计划后在本会话直接执行；集成、推送和 reload 仍另行确认。

## 目标与现状

减少目录发现及重复缓存查询的开销，不改变统计结果、覆盖范围、命令或报告格式。已有磁盘缓存的上轮本机测量为 744/610/650 ms，独立目录发现为 241 ms；这些不是优化后的承诺。

## Approaches

1. 仅优化目录发现：利用 Dirent、减少 lstat、有界并发。改动最小，但每次仍重读和校验全部统计 JSON。
2. 目录发现加进程内快照缓存：同时减少目录等待和重复 JSON 读取/解析，保留现有磁盘缓存。推荐并作为本轮方案；具体并发和额度是作者建议，不是用户指定值。
3. 持久化时间索引/数据库：可能降低更大历史的查询成本，但首次构建、并发、迁移及子代理依赖处理复杂，本轮不采用。

## 目录发现

- 保留 agent sessions 与当前自定义会话目录，根目录 realpath、重叠去重、只收集普通 JSONL 文件、最终路径排序。
- 利用 readdir 的 Dirent 类型跳过符号链接和无关文件，不再为每个文件额外 lstat；读取阶段仍核对源文件。
- 目录采用有界队列/分层批次，最多 8 路处理，不创建无界 Promise；目录进入时检查非符号链接，维持现有扫描边界。
- 保留直接选择根目录符号链接的支持，不跟随内部符号链接；缺失路径和权限诊断语义不变。

## 内存快照缓存

- 每个扩展实例持有独立快照存储，collectUsage 可选接收该存储；不使用跨实例无限增长的全局缓存。
- 按 cacheDir 与规范源路径隔离，缓存的只是已经解析的统计 FileSnapshot，不保存正文或最终报告。
- 建议上限：4096 个文件及按序列化统计元数据估算的 64 MiB 额度；额度不是精确 JavaScript 堆用量承诺。超大单项不接纳，容量满按有界淘汰处理；同一对象重复命中不重新序列化计重。
- 每次查询仍发现文件、检查源文件身份/大小/mtime/ctime；未变化才复用已验证的内存快照。变化时沿用现有追加边界/前缀校验或完整重建，不直接信任旧数据。
- 删除或不可读取的文件不累计旧快照；未被本次发现的文件不能因为内存仍有数据而继续计入。
- 磁盘缓存保留协议 4 和原子写入。新快照只有在已有有效磁盘副本或保存成功后才接纳进内存；保存失败不通过内存命中掩盖诊断或阻止下次重试。
- 每次重新执行时间窗口过滤、事件去重、继承历史与父子协调。不缓存最终总量，不用 TTL 返回旧结果，不按文件年龄跳过历史。

## 边界

- 不新增命令、配置项、依赖、后台监视器或模型调用；不修改 settings。
- 保留隐藏精度警告、真正错误提示、provider/model 明细和已删除的来源脚注状态。
- 不优化或改变计费口径，不承诺恶意文件元数据伪造/原地改写的防篡改保证。
- 沿用隔离 worktree、本会话实现；不新增子代理委派。独立审查未获授权，最终明确仅有作者自检。
- 本轮执行不自动授权合入、推送或 /reload。

## 验收

- 先写能证明减少冗余文件检查、有界并发及快照复用的失败回归，再实现。
- 覆盖根目录别名、重叠根、深层/宽目录、内部链接、损坏/缺失路径及受限权限。
- 覆盖缓存容量/淘汰/超大项、实例及缓存目录隔离、重复查询、追加、替换、同大小改写、删除、缓存不可写及恢复、并发查询。
- 完整测试、严格类型检查、打包预检、真实 Pi RPC 和 bundled loader 通过；统计分项与现有实现一致。
- 使用独立临时缓存和固定查询终点，对同一批源文件比较旧实现、新实现首次及重复查询；先核对整体、模型组和记录数，再报告目录与端到端耗时。区分磁盘已有缓存与真正无缓存冷扫描，不把采样 inclusive 时间相加。
- 只记录聚合结果和性能数据，不将真实对话正文写入仓库。最后同步行为档案并询问集成。
