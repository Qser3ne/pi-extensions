## 现有查询链路

1. discoverFiles 逐目录遍历，并对每个条目串行 lstat。
2. 4 个 worker 从磁盘读取每个统计快照，JSON.parse 并逐记录校验。
3. readUsageFile 即使命中文件缓存，仍 open → stat → close；变化文件解析追加或完整重建。
4. 重建继承历史、规范化子代理引用、协调父子汇总，再按窗口去重聚合。
5. 查询之间没有持久的进程内快照缓存，重复调用仍重读磁盘统计 JSON。

## 本机测量

2026-11-09，Node.js 22.23.4；只读本机 sessions，不改动源历史。将现有扩展统计缓存复制到 /tmp 独立目录测量，不改动运行中的扩展缓存。没有采集或写入对话正文。

- 源会话：462 个 JSONL，历史目录约 1.1 GB。
- 起始统计快照：462 个，均协议 4，逻辑大小 9,427,226 字节。
- 同一 7d 查询终点下，已有磁盘缓存的三次查询：744 / 610 / 650 ms。
- 三次整体 usage、models 和 recordCount 完全相等；9,046 条去重记录、11 个有用量组合。
- 独立目录发现测量：241 ms。
- 另对 5 次已有缓存查询采样：目录 walk、快照加载/验证、文件打开/元数据检查仍有明显工作；不能把异步采样的 inclusive 时间当作互不重叠的阶段耗时相加。
- 以上不是冷扫描、其他机器或未来优化后的性能承诺；未测无缓存全量扫描。

## 建议（尚未实施）

### 1. 低风险组合，优先推荐

- 利用已有 Dirent 信息避免对无关条目再次 lstat；对目录/文件检查采用有界并发，维持内部符号链接不跟随的扫描边界。
- 增加有内存/记录数上限的进程内快照缓存。仍核对源文件身份、大小和时间元数据；未变源文件直接复用已验证快照，变化源文件走现有追加/重建校验，删除文件不继续累计。
- 仍每次重新处理查询窗口与父子协调，不直接复用过期的最终总数，不以 TTL 返回旧数据。
- 与磁盘缓存共存，Pi 重启后继续可用；不缓存正文，避免无界增长。
- 保留当前快照协议/统计口径；用同终点冷/热/追加/改写/删除及跨进程用例验证结果一致，再比较耗时。

收益来自减少重复目录 I/O 与 JSON 解析，不来自少算历史。实际收益必须在实现后再测，不能保证固定倍数。

### 2. 持久化时间索引，作为后续选择

为大规模历史建立可重建的持久索引，按窗口读取候选事件，同时保留 fork/继承历史与子代理依赖。首次构建、升级、并发写和损坏恢复成本明显更高，不建议先为当前约 0.6–0.75 秒的已有缓存查询重做整个存储层。

### 不建议的捷径

- 仅按会话文件 mtime 或创建时间跳过旧文件：窗口归属是事件时间，且父子协调需要窗口之前的历史覆盖信息。
- 直接返回上次最终报告：查询终点持续移动，活跃记录、删除与重写都可能改变结果。
- 仅无限增加并发：可能增加随机 I/O、内存与文件描述符压力。
