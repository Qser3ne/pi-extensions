Node.js 22.23.4，固定查询截止点；使用独立临时缓存，不修改源会话或运行中的扩展缓存。时间为毫秒。旧版指 main 当时的 c55756a，不混用先前 462 会话的基线。

| 真实历史：503 文件，9141 条去重记录，11 模型组 | 三次耗时 |
|---|---|
| 旧版磁盘热查询 | 380 / 283 / 282 |
| 新版磁盘热查询（不使用内存存储） | 230 / 203 / 209 |
| 新版首次填充内存 | 238（一次） |

测量期间检测到 1 个源文件元数据变化，但固定截止点下比较结果仍一致；不声称数据集完全静止。运行顺序、OS 文件缓存、后台活动和内存容量都会影响数据，不承诺固定倍数。

## Rulings I made

1. 通过 scratch 的可执行副本运行流程脚本：已安装脚本无执行权限；不改共享技能、无产品影响。错误副本只会阻塞流程记账。
2. 强制两级缓存完全清空需删除磁盘缓存并 /reload：进程内快照刻意跨磁盘读取保留。仅删除目录可能继续复用已核对源文件的内存统计；代价是强制冷扫描多一个 reload 步骤，README 与档案已明确。
3. 手动 live TUI /reload、其他 Pi/OS 版本、崩溃注入及真实历史无缓存冷扫描仍为覆盖限制：不声称验证。代价是这些环境仍需单独验收。
